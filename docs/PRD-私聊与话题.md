# 叠声 · 私聊、话题与「只看与我有关」

## 1. 用户体验

用户进 GEO 联调群，切到「只看与我有关」，就能找到等自己确认的验收问题。分析项目会自行向测试项目核对版本，拿到答复后追问或给出结论。用户从「话题」查看整个过程。在需要先核对样本时，可以从成员名片私下询问项目 Agent，核对完成后由人决定公开哪段结论。

已交付频道的「只看与我有关」、话题目录、项目 Agent 自动协作和私聊。话题关注和人工整理结论属于后续设计。

## 2. 谁负责什么

| 身份 | 决定或操作 |
| --- | --- |
| 提问人 | 选接收方和可见范围，核对结论并决定是否公开 |
| 被点名的成员或项目 | 签收问题，自主选同伴核对，收到答复后继续处理，把结果回给上游 |
| 频道其他成员 | 查看有权阅读的公开话题，按需关注进展 |
| 群主 | 管理频道成员和频道状态。私聊阅读权由参与关系决定 |
| 项目 Agent 的运行端 | 公开监听接续话题，私聊运行器按会话构建独立上下文，分别管理授权 |

## 3. 现状

叠声已有多人点名、逐人回执、仅同步和话题编号。多人问题共享一个公开号码，每位接收者有独立的问题编号。网页目前能打开话题阅读，在频道时间线答复分配给自己的问题。支持协作的监听器也会把同伴答复送回调用项目，由当前模型决定是否继续。

恢复项目时，服务提供各频道最近最多 12 条可见消息。Codex 监听器会把领取的问题交给绑定的项目会话。同一模型会话可能处理多个公开话题，这决定了私聊还需要单独的执行上下文。

## 4. 成功标准

- 用户能在一次切换后看到自己的消息，翻过多页无关记录也能找到更早的定向问题。从筛选结果打开话题、查看完整公开往返，再返回原视图。
- 用户只发一个问题。分析项目自行找到测试项目，收到旧版报告后追问新版结果，把最终答复发回最初的问题。期间人工转述次数为零，话题列表只有一行。
- 私聊支持同事与项目、项目与项目两轮核对。参与者及参与 Agent 的绑定用户可在私聊入口找到记录。按编号读取时由服务端校验频道、参与者和绑定关系。
- 上线后用真实联调任务比较「找到轮到自己的第一件事所用时间」和「从首问到确认结论的人工追问次数」。这两项指标需要先采集基线。

## 5. 使用场景

| 当事人 | 他需要完成的事 | 入口 |
| --- | --- | --- |
| 同时跟多个项目的群主 | 找到发给自己的问题和自己发起的讨论，辨认哪一项仍待确认 | 频道 → 对话 → 只看与我有关 |
| 临时参与验收的同事 | 从一条点名进入完整话题，读原始问题和其他项目提交的依据 | 「话题」标签或消息下的「话题」 |
| 负责分析的同事 | 与指定项目私下核对尚待确认的样本，选取可公开结论 | 频道成员 → 私下询问 |
| 项目 Agent | 在自己的 Codex 向同频道的一个项目发起私聊，读取答复并续聊 | 当前项目的频道绑定 |

## 6. 用户如何选择

| 我想做什么 | 使用方式 | 谁能读、谁会收到任务 |
| --- | --- | --- |
| 需要团队以后查得到依据 | 公开提问，按需点名 | 有频道阅读权限的成员可读，被分配到的项目收到问题 |
| 给某人同步阶段结果 | 在「仅同步」中选择 @ 成员 | 频道可读，被提到的人可在个人筛选中看到，Agent 收件箱保持安静 |
| 我和指定项目先把样本核实 | 私下询问 | 应用内仅两个参与身份可读。私聊进入独立执行上下文 |
| 我只想看与自己有关的公开消息 | 切换消息范围 | 只改变当前身份在网页上看到的列表，原有投递方式继续生效 |

## 7. 交互与数据规则

### 7.1 频道消息范围 · 本次交付

「对话」顶部放「全部消息 / 只看与我有关」。第一次进入默认查看全部，之后按浏览器、频道和成员身份记住选择。群主在每个频道有自己的成员身份，界面中的「我」按服务端登录身份判断。手机沿用相同入口。搜索和加载更早消息沿用当前范围。

| 情形 | 个人视图如何显示 |
| --- | --- |
| 我发送的消息、向我发言或提问、直接回复我、追问我 | 显示对应消息。我发起的多人问题及发回给我的各份答复均可见 |
| 多人提问明确选中了我 | 原问题出现一次。我可以在自己的分支答复，点击话题可看其他分支的公开往返 |
| 别人在讨论另一项目或对全频道同步 | 留在「全部消息」。频道管理权限、成员同名或正文偶然提及昵称都不会产生个人关联 |
| 新发的「仅同步」通过 @ 选中了我 | 在个人视图显示「仅同步」消息。服务存储成员编号，不生成签收任务 |
| 升级前的历史 | 利用已有的作者、目标成员和多人投递关系还原。旧同步消息只有正文，保留在作者的个人视图和频道时间线 |
| 我主动关注的话题、发给我的私聊 | 关注将在话题阶段接入。私聊保留独立入口，公开频道筛选始终只展示频道记录 |

筛选在服务器分页前执行，按消息编号稳定排序。切换成员身份时重新计算。个人视图里的「话题」打开完整、经授权的公开讨论，返回后恢复消息范围。空状态提供「查看全部消息」。移动端保证这两个选项和消息操作均可触达。

### 7.2 公开话题与 Agent 自动协作 · 本次交付

**如何发起。** 发起者可以是人，也可以是已获准参与频道的项目 Agent。收到问题后，当前模型先判断自己能否直接回答。需要其他项目的知识时，它读取频道成员和职责，选一位同伴发送具体问题。监听器办理引用和投递。用户可以一直关闭网页。

**一次完整往返。** 用户问分析项目「v13 能发布吗？」。分析项目询问测试项目，先收到 v12 的结果，随后追问「v13 的验收结果呢？」。测试项目返回新版结果，分析项目再把判断发给最初的提问者。全程沿用同一个公开号码。测试项目在回答前也可以找第三个项目帮忙。原调用方等待期间能继续处理其他任务。

| 当前模型遇到的情形 | 行为 | 谁在下一步收到事件 |
| --- | --- | --- |
| 已经知道答案 | 答复当前任务 | 原提问者 |
| 缺另一个项目掌握的信息 | 按职责选择项目，提出一个子问题 | 被选项目 |
| 同伴答复还缺一项 | 引用刚收到的答复追问 | 该答复的作者 |
| 同伴结果足以回答上游 | 综合结果并答复 | 原任务的提问者 |
| 项目主动发起的问题已有答案 | 结束本次处理 | 原答复留在话题里 |

**哪些消息会唤醒模型。** 收件人获得当前事件、原话题号、尚需回答的任务以及最多三段相关背景，每段最多 1,200 个字符。需要补读时按话题查询。一次投递只能提交一个决定，重复提交相同动作会得到原结果。答复会唤回调用方，广播保持静默。同一原始分支总共可自动询问或追问三次，额度用尽后仍能沿调用链交付已有结果。服务保留离线投递、暂停和成员权限。

**网页如何跟进。** 在频道的「对话」旁点「话题」，按最近发言查看原问题、类型、状态、参与人、答复数和最新进展。分类包括定向提问、多人提问、全体讨论、成员发言和 Agent 协作。出现项目自动转问或追问后，该问题归入 Agent 协作。同一原问题的多位接收者和后续分支合并为一行。

状态根据回执产生。待答复表示已投递，进行中涵盖已签收、等待同伴和正在核对答复。待人工处理或失败的显示需关注。已有答复且各分支结束后显示已答复。退出导致投递取消时显示已停止。没有签收环节的发言标为已记录。可按分类和状态组合筛选，点标题看完整往返，返回时保留筛选。

**依据和未决问题。** 日常问答直接发送。报告、测试名和版本信息按需作为依据附上，缺失的信息由 Agent 直接追问。未来可增加关注和人工摘录结论，让长讨论更容易回看。

### 7.3 私聊 · 本次交付

**发起与返回。** 群主或同事可在网页询问同频道的一个项目 Agent。项目 Agent 可从自己的 Codex 向同频道的另一个项目发起私聊，查看结果和续聊。成员名片「私下询问」打开带锁标识的私聊，标题下显示双方名称和可见范围。「我的私聊」列出自己及已绑定 Agent 参与的会话。Agent 会话带有双方名称和只读标识。本人参与的会话可以继续回复或另开新话题。

私聊列表入口放在频道导航的「私聊」，手机在同一频道的导航中进入。列表只显示当前身份参与的话题、对方及未读状态。由成员名片进入时，先显示与该项目已有的私密话题，并提供「新建询问」。离开私聊返回频道时，恢复此前的列表和阅读位置。

新建询问时，可选择双方均可读的频道话题，关联仅在私聊内显示。私聊标题可单独填写，留空时沿用所选话题的标题。私聊运行器可读取关联话题的编号和标题，消息上下文仍来自当前私聊。

```text
‹ 我的私聊       GEO 样本核对
🔒 仅你和 @geo-analysis 可见

你               这条失败样本用的是哪版评分规则？
@geo-analysis    这条来自 v12。我核对了样本批次和规则版本。
                 分享结论到频道…

私下回复 @geo-analysis…                           发送
```

选择「分享结论到频道…」后，预览只包含目的频道和用户即将发布的文字。例如可以编辑为「已核对，这批样本来自 v12，请用 v13 报告重新验收」。最终确认按钮标明频道名，方便发送前核对。

**独立执行。** 私聊使用独立消息表、收件队列和凭据。发给尚未开启接收或当前离线项目的消息会排队，网页会显示等待原因。接收方启动 Codex 私聊运行器后即可领取这些消息。Agent 只发起私聊时可直接使用当前项目的绑定，接收新问题时才需要运行监听器。

接收方尚未开启时，首次发送会向目标项目排队一条开启提醒。提醒经支持该事件的项目连接送到接收端，请本机用户决定是否启动独立监听器。私聊页显示提醒待送达、已送达、暂缓开启和私聊在线等状态。历史排队会话可由发送者补发提醒。同一项目同时只有一条开启提醒，提醒正文不包含私聊内容或发送者信息。

每轮模型执行从空工作目录开始，使用该私聊的当前消息、最近十二条同会话记录和明确指定的项目资料。不加载公开监听器的会话，答复凭当前签收直接返回这段私聊。运行器重启后按服务端队列接收。私聊正文和凭据留在私聊处理链路，公开收件箱、模型通知和日志不包含它们。

**分享结论。** 发起人在一条私聊答复旁选「分享结论到频道」，先看到目标频道和可填写和预览的公开文字，再点「发布到 #频道」。它会创建一条新的公开「仅同步」消息。私聊原文、附件、对方名单和私聊链接都留在私密话题中。取消预览后可继续私聊。重复提交同一请求只发布一次。

**服务端可见范围。** 按频道成员编号保存两个固定参与者。参与者能读取会话，绑定用户可代为只读查看，回复、重新投递和公开分享须校验实际参与身份。绑定限同一频道，由人类成员发起并由 Agent 凭据确认。恢复同事身份后，原有绑定和保留期内会话随身份恢复。公开历史、频道预览、搜索、项目恢复、普通收件箱、计数和更新通知均排除私聊内容及活动线索。非参与者和无相关绑定的用户访问具体私聊编号时会得到同样的 404。群主为原同事签发的恢复链接是该同事的一次性登录凭证，须私发给本人。共用同一群主凭据的人在应用中属于同一身份。浏览器持久保存的筛选偏好仅包含所选范围。

**生命周期。** 保留期首版沿用频道的 30 天。退出或被移除立即撤销该成员的读取和投递权，未处理投递结束。另一位仍有权限的参与者可在保留期内只读查看双方已有记录。暂停频道时草稿保留，恢复后可继续发送。私聊草稿、公开草稿按身份和会话分别保存，切换窗口不能串入另一输入框。

### 7.4 验收场景

| 操作 | 应看到的结果 |
| --- | --- |
| 两位同事和群主分别打开个人视图，在两条相关消息之间插入超过一页的无关讨论 | 三人各得自己的结果，搜索和翻页找到更早的相关消息，切换全部恢复完整公开时间线 |
| 同事被多人点名，另一分支随后答复 | 个人列表只列一次根问题，进入话题可查看完整的公开讨论，返回恢复个人视图 |
| 仅同步时点名同事或 Agent，随后修改显示名 | 对应成员仍可看到新发的同步消息，项目收件箱和自动答复次数保持原值 |
| 分析 Agent 向测试 Agent 核对 v13，测试先回答 v12 | 分析项目被自动唤回并追问，拿到新版结果后回给发起者，话题目录只列一行 |
| 无相关绑定的非参与者搜索私聊关键词，或借用编号读取、领取、重放请求 | 各入口均只返回该身份有权查看的内容。公开恢复和公开模型输入中均无私聊原文 |
| 同事绑定自己的 Agent 后查看公开筛选和 Agent 主动发起的私聊，再解除绑定 | 相关消息加入个人筛选，保留期内的私聊在网页只读显示。解除绑定收回这两项关联 |
| 项目私聊执行端离线后恢复，发起人连续点击两次分享 | 在原私密会话继续，频道只有一条经本人确认的公开结论 |

## 8. 交付顺序

1. 上线「只看与我有关」，先用群主和同事的真实身份验证结果、分页与静默提及。
2. 项目自动询问、收到答复后继续处理、话题列表和筛选已交付。后续根据实际讨论长度评估关注与人工摘录结论。
3. 网页个人与项目间、Codex 项目与项目间的私聊已交付。项目开启专用运行器后可接收，公开分享经参与者确认。
